Methodology (rules v1)

  • Demo day = date the winners/finalists were publicly announced (linked source).
  • GitHub: commits on the default branch of the linked public repo (committer date). Private, missing or unlinked repo → unknown, never “inactive”.
  • Checkpoint N (30/90/180d): “active” if ≥1 commit in the 30 days ending N days after demo day; “pending” if that date hasn’t arrived.
  • Site: HTTP GET of the listed site; 2xx/3xx and not a parked/“deployment not found” page = up. Bot walls (401/403/429/503) = unknown.
  • X: date of the project account’s most recent post (any post type). Checked live only when an API token is available, otherwise from a dated snapshot, otherwise unknown.
  • Token: DexScreener lookup only when a token address is listed. Raise: manual, sourced entries only. Contract activity: planned (v2).
  • Status: Graduated (sourced raise or token FDV ≥ $1M) → Active (commit or post ≤ 30 days) → Recent (31–90 days) → Site up only → Quiet (no public commit/post in 90 days, or none found since demo day) → Insufficient data.
  • Labels describe public signals only. Private repos, pivots and renames are common — a quiet label is not a judgement on the team. Full rules.
